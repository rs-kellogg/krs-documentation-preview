Description#

Revelio Labs compiles public professional profiles, job postings, and employee reviews into standardized, company-linked datasets. The tables fall into five groups:

  • Individual profiles: one row per person, with predicted demographics, education, skills, and work history

  • Positions: one row per employment spell, with company, location, role, seniority, and salary estimates

  • Job postings: one row per posting, with company, role, location, salary, and source flags, plus a separate table of posting text

  • Company and school reference tables: company identifiers, school mapping, and regions

  • Lookup and sentiment tables: role and skill taxonomies, layoffs, and company sentiment scores

Revelio’s data is available on WRDS in the revelio library. A bulk export of most tables is also stored as Parquet files on KLC, where we query it with DuckDB on the KLC file system without moving data over the network. Start with Querying with DuckDB on KLC. The WRDS-based workflow is covered in the Revelio Labs WRDS example.

Access#

Access is restricted to members of the Northwestern University community. Email Kellogg Research Support to request access.

  • KLC: requires a KLC account. See How to Access KLC if you do not have one.

  • WRDS: requires a WRDS account with Revelio access. See the WRDS page.

Important

individual_user and the individual_* tables describe real people, including names and model-inferred demographics. Use of this data is subject to Revelio’s license terms. Do not use it to re-identify individuals, and do not share raw records outside your approved research project.

Querying with DuckDB on KLC#

DuckDB reads the Parquet files in place. On KLC main, cap every session at 16 threads and 128 GB. Use a KLC Reserve job when the query needs more than that, or when a long scan should leave the shared login node.

Before You Start#

  • Log in to KLC. See How to Access KLC if you do not have an account.

  • Create a conda environment under /kellogg/proj/<your-netid>/. See Conda Environments on KLC.

  • Store views and extracts under /kellogg/proj/<your-netid>/revelio. Home directories are 80 GB.

  • Send DuckDB spill files to /scratch/<your-netid>/duckdb_tmp.

module load mamba/24.3.0
mamba create -p /kellogg/proj/<your-netid>/envs/revelio-duckdb -c conda-forge python-duckdb
source activate /kellogg/proj/<your-netid>/envs/revelio-duckdb
mkdir -p /kellogg/proj/<your-netid>/revelio /scratch/<your-netid>/duckdb_tmp

For R, add duckdb and DBI to an R environment from the same conda page. Replace <your-netid> in every path below.

When a query exceeds memory_limit, DuckDB spills to temp_directory and keeps running. When the spill would pass max_temp_directory_size, raise that cap or move the query to a KLC Reserve job with a higher --mem. See High-Memory Jobs for requests above 128 GB.

Note

memory_limit applies to DuckDB’s own buffers. Converting a result to pandas or R with .df() or dbGetQuery() allocates additional memory outside the limit. Return an aggregate or a small extract.

Query Rules#

  • Set threads = 16 and memory_limit = '128GB' when you connect on KLC main. Raise either value only in a KLC Reserve job that requests those resources.

  • Name the columns you need. DuckDB then skips the other Parquet columns, including description and review text.

  • Filter and aggregate in DuckDB. Do not pull individual_positions, postings_cosmos, or individual_user_skills into pandas, Polars, or R.

  • Save an extract under /kellogg/proj/<your-netid>/revelio/ for repeated work. The files are not partitioned by rcid, so a firm filter still reads many parts.

  • Run DESCRIBE or an unfiltered COUNT(*) to inspect a table. Both read Parquet metadata only.

Create Views Once#

A view gives each table a short name and hides the file glob. This script stores view definitions in a small DuckDB file. DuckDB reads the Parquet files when you query a view. Run the script again when a new snapshot folder replaces the dates below. The connection uses the same 16-thread and 128 GB cap.

import duckdb

ROOT = "/kellogg/data/revelio"
JOBS = f"{ROOT}/Oct52026/revelio_job_postings"
INDIV = f"{ROOT}/Oct192026/revelio_individual"
MISC = f"{ROOT}/Oct192026/revelio"

tables = {
    # Job postings
    "postings_cosmos": JOBS,
    # Individual profiles
    "individual_positions": INDIV,
    "individual_positions_raw": INDIV,
    "individual_user": INDIV,
    "individual_user_raw": INDIV,
    "individual_user_education": INDIV,
    "individual_user_education_raw": INDIV,
    "individual_user_skills": INDIV,
    # Company, lookup, and miscellaneous tables
    "company_mapping": MISC,
    "individual_role_lookup_v2": MISC,
    "individual_role_lookup_v3": MISC,
    "postings_role_lookup_v2": MISC,
    "postings_role_lookup_v3": MISC,
    "individual_user_skill_lookup": MISC,
    "layoffs": MISC,
    "months": MISC,
    "regions": MISC,
    "school_mapping": MISC,
    "sentiment_individual_reviews": MISC,
    "sentiment_role_lookup": MISC,
    "sentiment_scores": MISC,
}

# Replace <your-netid> with your NetID
con = duckdb.connect(
    "/kellogg/proj/<your-netid>/revelio/revelio_views.duckdb",
    config={
        "threads": 16,
        "memory_limit": "128GB",
        "temp_directory": "/scratch/<your-netid>/duckdb_tmp",
        "max_temp_directory_size": "200GB",
    },
)
con.execute("SET preserve_insertion_order = false")

for name, base in tables.items():
    con.execute(
        f"CREATE OR REPLACE VIEW {name} AS "
        f"SELECT * FROM read_parquet('{base}/{name}/*.parquet')"
    )

# Filtered joins against posting text. For a long extract, use the part-by-part script.
raw_parts = [f"'{JOBS}/postings_cosmos_raw_p{i}/*.parquet'" for i in range(10)]
con.execute(
    "CREATE OR REPLACE VIEW postings_cosmos_raw AS "
    f"SELECT * FROM read_parquet([{', '.join(raw_parts)}])"
)

con.close()

postings_cosmos_raw unions all 10 posting-text tables. Use it for a filtered join. For a long extract, use the part-by-part script in Extract Posting Text for a Country and Year.

Save an Extract#

Write the columns you need to your own Parquet file, then query the extract for repeated work. On DuckDB, preserve_insertion_order is already false on the connection above.

con.execute("""
    COPY (
        SELECT
            user_id,
            position_id,
            rcid,
            startdate,
            enddate,
            country,
            weight,
            salary
        FROM individual_positions
        WHERE rcid = 123456
    ) TO '/kellogg/proj/<your-netid>/revelio/positions_rcid_123456.parquet'
      (FORMAT parquet, COMPRESSION zstd)
""")
print(con.sql("""
    SELECT COUNT(*)
    FROM read_parquet('/kellogg/proj/<your-netid>/revelio/positions_rcid_123456.parquet')
""").df())

positions = conn.raw_sql(
    """
    SELECT user_id, position_id, rcid, startdate, enddate,
           country, weight, salary
    FROM revelio.individual_positions
    WHERE rcid = 123456
    """,
    date_cols=["startdate", "enddate"],
)
positions.to_parquet(
    "/kellogg/proj/<your-netid>/revelio/positions_rcid_123456.parquet",
    index=False,
)
print(len(positions))

Monthly Headcount from the Extract#

Compute a weighted monthly headcount for 2019 to 2023. The longer WRDS walkthrough, including separation rates and a plot, is the Revelio Labs WRDS example.

df = con.sql("""
    WITH months AS (
        SELECT CAST(m AS DATE) AS month_start
        FROM generate_series(
            DATE '2019-01-01', DATE '2023-12-01', INTERVAL 1 MONTH
        ) AS t(m)
    )
    SELECT
        m.month_start,
        SUM(p.weight) AS weighted_headcount,
        COUNT(*) AS n_positions
    FROM months AS m
    JOIN read_parquet('/kellogg/proj/<your-netid>/revelio/positions_rcid_123456.parquet') AS p
      ON p.startdate <= m.month_start
     AND (p.enddate IS NULL OR p.enddate > m.month_start)
    WHERE p.country = 'United States'
    GROUP BY m.month_start
    ORDER BY m.month_start
""").df()
print(df.head())

df = conn.raw_sql(
    """
    SELECT
        gs.month_start,
        SUM(p.weight) AS weighted_headcount,
        COUNT(*) AS n_positions
    FROM generate_series(
        DATE '2019-01-01', DATE '2023-12-01', INTERVAL '1 month'
    ) AS gs(month_start)
    JOIN revelio.individual_positions AS p
      ON p.startdate <= gs.month_start
     AND (p.enddate IS NULL OR p.enddate > gs.month_start)
    WHERE p.rcid = 123456
      AND p.country = 'United States'
    GROUP BY gs.month_start
    ORDER BY gs.month_start
    """,
    date_cols=["month_start"],
)
print(df.head())

Use KLC Reserve Above This Budget#

Submit the same query to KLC Reserve when it needs more than 16 threads or more than 128 GB, or when you want a long scan off the shared node. The script below reads SLURM_NTASKS and SLURM_MEM_PER_NODE (megabytes, set by --mem) and sets memory_limit to about 90% of that grant. Outside a SLURM job it uses the KLC main cap of 16 threads and 128 GB.

The sample query scans postings_cosmos. On KLC main, run it at 16 threads and 128 GB. Raise --ntasks and --mem in the batch script when you need more. For RAM above a standard Reserve node, see High-Memory Jobs.

Save this script as revelio_job.py:

import os
import duckdb

if os.environ.get("SLURM_JOB_ID"):
    threads = int(os.environ["SLURM_NTASKS"])
    mem_mb = int(os.environ["SLURM_MEM_PER_NODE"])
    memory_limit = f"{int(mem_mb * 0.9 / 1024)}GB"
else:
    threads = 16
    memory_limit = "128GB"

con = duckdb.connect(
    "/kellogg/proj/<your-netid>/revelio/revelio_views.duckdb",
    read_only=True,
    config={
        "threads": threads,
        "memory_limit": memory_limit,
        "temp_directory": "/scratch/<your-netid>/duckdb_tmp",
        "max_temp_directory_size": "200GB",
    },
)
con.execute("SET preserve_insertion_order = false")

con.sql("""
    SELECT date_trunc('month', post_date) AS post_month, COUNT(*) AS n_postings
    FROM postings_cosmos
    GROUP BY post_month
    ORDER BY post_month
""").write_csv("/kellogg/proj/<your-netid>/revelio/postings_by_month.csv")

Save this as revelio_job.sh:

#!/bin/bash
#SBATCH --account=kellogg
#SBATCH --partition=kellogg
#SBATCH --job-name=revelio-duckdb
#SBATCH --nodes=1
#SBATCH --ntasks=16
#SBATCH --mem=128G
#SBATCH --time=04:00:00
#SBATCH --output=logs/slurm-%j.out

module purge
module use --append /kellogg/software/Modules/modulefiles
module load mamba/24.3.0
source activate /kellogg/proj/<your-netid>/envs/revelio-duckdb

mkdir -p /scratch/<your-netid>/duckdb_tmp
python revelio_job.py

#SBATCH --output is opened when the job starts, so create the log directory before you submit. For submission options, monitoring, and tuning, see Submitting SLURM Jobs.

mkdir -p logs
sbatch revelio_job.sh

Layoffs by State and Year#

df = con.sql("""

    GROUP BY state, layoff_year

Employee Review Ratings by Year#

Education by Degree and Field#

df = con.sql("""
    SELECT e.degree, e.field, COUNT(*) AS n_records

    JOIN school_mapping AS s ON e.rsid = s.rsid
    JOIN individual_user AS u ON e.user_id = u.user_id
    WHERE s.school_cleaned ILIKE 'northwestern university'
      AND u.user_country = 'United States'
    GROUP BY e.degree, e.field
    ORDER BY n_records DESC
    LIMIT 25
""").df()
print(df)

df = conn.raw_sql("""
    SELECT e.degree, e.field, COUNT(*) AS n_records
    FROM revelio.individual_user_education AS e
    JOIN revelio.school_mapping AS s ON e.rsid = s.rsid
    JOIN revelio.individual_user AS u ON e.user_id = u.user_id
    WHERE s.school_cleaned ILIKE 'northwestern university'

Part-by-Part DuckDB Script

The script below writes one Parquet file per postings_cosmos_raw_p* table, skips files that already exist, and writes each file under a temporary name so a failed job leaves no partial output.

import os
from pathlib import Path

import duckdb

JOBS = "/kellogg/data/revelio/Oct52026/revelio_job_postings"
OUT = Path("/kellogg/proj/<your-netid>/revelio/hong_kong_postings_2026")
TMP = Path("/scratch/<your-netid>/duckdb_tmp")
OUT.mkdir(parents=True, exist_ok=True)
TMP.mkdir(parents=True, exist_ok=True)

if os.environ.get("SLURM_JOB_ID"):
    threads = int(os.environ["SLURM_NTASKS"])
    mem_mb = int(os.environ["SLURM_MEM_PER_NODE"])
    memory_limit = f"{int(mem_mb * 0.9 / 1024)}GB"
else:
    threads = 16
    memory_limit = "128GB"

con = duckdb.connect(config={
    "threads": threads,
    "memory_limit": memory_limit,
    "temp_directory": str(TMP),
    "max_temp_directory_size": "200GB",
})
con.execute("SET preserve_insertion_order = false")

con.execute(f"""
    CREATE TEMP TABLE target_postings AS
    SELECT DISTINCT CAST(job_id AS HUGEINT) AS job_id, rcid, company, post_date
    FROM read_parquet('{JOBS}/postings_cosmos/*.parquet')
    WHERE country = 'Hong Kong'
      AND post_date >= DATE '2026-01-01'
      AND post_date <  DATE '2027-01-01'
      AND job_id IS NOT NULL
""")
n_ids = con.execute("SELECT COUNT(*) FROM target_postings").fetchone()[0]
print(f"{n_ids:,} target postings")

for i in range(10):
    out = OUT / f"postings_cosmos_raw_p{i}_matched.parquet"
    if out.exists():
        print(f"p{i}: already done")
        continue
    partial = out.with_suffix(".parquet.partial")
    con.execute(f"""
        COPY (
            SELECT t.*, r.title_raw, r.jobtitle_translated, r.description
            FROM read_parquet('{JOBS}/postings_cosmos_raw_p{i}/*.parquet') AS r
            JOIN target_postings AS t
              ON CAST(r.job_id AS HUGEINT) = t.job_id
        ) TO '{partial}' (FORMAT parquet, COMPRESSION zstd)
    """)
    partial.rename(out)
    print(f"p{i}: done")

total = con.execute(f"SELECT COUNT(*) FROM read_parquet('{OUT}/*.parquet')").fetchone()[0]
print(f"{total:,} matched rows")

Read the result with read_parquet('/kellogg/proj/<your-netid>/revelio/hong_kong_postings_2026/*.parquet'). Submit the script with the sbatch pattern in Use KLC Reserve Above This Budget when it needs more than 16 threads or 128 GB.
