Description#

Multidisciplinary coverage of over 10,000 journals in the sciences, social sciences, and arts and humanities, as well as published proceedings for over 12,000 conferences per year, and over 50,000 scholarly books. The library web interface searches the database and lists articles that cite a given work.

On KLC, the 2025 extract is a DuckDB file. papers has one row per publication. paper_references has one row per cited reference. Query the file on the KLC file system. Start with Querying with DuckDB on KLC.

Access#

The Northwestern Library offers access to the web interface .

A limited amount of Web of Science data can be made available to a limited number of academic researchers on KLC. Query the DuckDB file at /kellogg/data/WOS/2025/db/wos2025.db. See How to Access KLC if you do not have an account. To inquire about this resource, contact Research Support .

Querying with DuckDB on KLC#

DuckDB reads /kellogg/data/WOS/2025/db/wos2025.db on the KLC file system. On KLC main, cap every session at 16 threads and 128 GB. Queries that filter, aggregate, or return a short sample stay on KLC main. Read When to Use KLC Reserve when you will load papers or paper_references into memory.

Before You Start#

  • Log in to KLC. See How to Access KLC if you do not have an account.

  • Create a conda environment under /kellogg/proj/<your-netid>/. See Conda Environments on KLC.

  • Save extracts under /kellogg/proj/<your-netid>/wos. Home directories are 80 GB.

  • Send DuckDB spill files to /scratch/$USER/duckdb_tmp. The connection snippet sets that path from the USER environment variable.

module load mamba/24.3.0
mamba create -p /kellogg/proj/<your-netid>/envs/wos-duckdb -c conda-forge python-duckdb
source activate /kellogg/proj/<your-netid>/envs/wos-duckdb
mkdir -p /kellogg/proj/<your-netid>/wos /scratch/$USER/duckdb_tmp

Replace <your-netid> in the environment path and the extract directory.

Where to Run the Query#

KLC main is the default. Check KLC Node Resources and use a node with at least 128 GB free. A cap of 16 threads stays within the 24-core limit on KLC main.

Query

Where to Run

A DuckDB query that filters, aggregates, or returns a limited sample, including DESCRIBE and COUNT(*)

KLC main, at 16 threads and 128 GB

Reading papers or paper_references in full into pandas, Polars, or R

When to Use KLC Reserve

Query Rules#

  • Set threads = 16 and memory_limit = '128GB' when you connect on KLC main. Raise either value only in a KLC Reserve job that loads either table into memory and requests those resources.

  • Name the columns you need.

  • Filter and aggregate in DuckDB. Return an aggregate or a small extract on KLC main.

  • Split pipe-delimited columns with string_split and unnest. Those columns are listed in Database Tables.

  • Run SHOW TABLES, DESCRIBE papers, or DESCRIBE paper_references to inspect the file. See Inspect the Database.

Open a Connection#

Open the database read-only. Set the cap on every connection, then run every later snippet in that same session.

import os
import duckdb

TEMP_DIRECTORY = f"/scratch/{os.environ['USER']}/duckdb_tmp"

con = duckdb.connect(
    "/kellogg/data/WOS/2025/db/wos2025.db",
    read_only=True,
    config={
        "threads": 16,
        "memory_limit": "128GB",
        "temp_directory": TEMP_DIRECTORY,
        "max_temp_directory_size": "200GB",
    },
)
con.execute("SET preserve_insertion_order = false")

Setting

Controls

KLC Main Value

threads

CPU threads for query execution

SET threads = 16;

memory_limit

Maximum memory DuckDB uses before spilling to disk

SET memory_limit = '128GB';

temp_directory

Where DuckDB writes spill files

SET temp_directory = '/scratch/<your-netid>/duckdb_tmp';

max_temp_directory_size

Cap on total spill-file size

SET max_temp_directory_size = '200GB';

preserve_insertion_order

false lowers memory use for large scans

SET preserve_insertion_order = false;

The Python snippet fills temp_directory from USER. The SQL value above is the same path with your NetID written out.

Confirm the active values in the same session:

df = con.sql("""
    SELECT current_setting('threads') AS threads,
           current_setting('memory_limit') AS memory_limit,
           current_setting('temp_directory') AS temp_directory
""").df()
print(df)

Where You Run

threads

memory_limit

KLC main

16

128GB

KLC Reserve

The --ntasks value you request

About 90% of the --mem value you request

When a query exceeds memory_limit, DuckDB spills to temp_directory and keeps running. When the spill would pass max_temp_directory_size, raise that cap. Loading the entire table into memory is covered in When to Use KLC Reserve. See High-Memory Jobs for requests above 128 GB.

Note

memory_limit applies to DuckDB’s own buffers. Converting a result to pandas with .df() allocates additional memory outside the limit. Return an aggregate or a small extract on KLC main.

Warning

Do not read papers or paper_references into pandas with SELECT *. papers includes full abstracts, and paper_references has one row per cited work. Aggregate, filter, or use LIMIT in DuckDB first.

Close the session when you are finished: con.close().

Example Queries#

Run these queries in the session from Open a Connection. Each snippet returns a small result.

Inspect the Database#

SHOW TABLES lists every table in the file. DESCRIBE lists columns and types. Definitions are in Database Tables.

print(con.sql("SHOW TABLES").df())
print(con.sql("DESCRIBE papers").df())
print(con.sql("DESCRIBE paper_references").df())

Overview#

Count papers, the year range, and the average number of cited references.

df = con.sql("""
    SELECT
        COUNT(*) AS total_papers,
        MIN(pubyear) AS earliest_year,
        MAX(pubyear) AS latest_year,
        ROUND(AVG(reference_count), 1) AS avg_references
    FROM papers
""").df()
print(df)

Top Journals#

Count papers by source title. source_title is stored in upper case.

df = con.sql("""
    SELECT
        source_title,
        COUNT(*) AS paper_count
    FROM papers
    WHERE source_title IS NOT NULL
    GROUP BY source_title
    ORDER BY paper_count DESC
    LIMIT 10
""").df()
print(df)

Papers per Year#

Count papers and open-access papers for the latest years. is_oa is Yes or No.

df = con.sql("""
    SELECT
        pubyear,
        COUNT(*) AS papers,
        SUM(CASE WHEN is_oa = 'Yes' THEN 1 ELSE 0 END) AS open_access
    FROM papers
    WHERE pubyear IS NOT NULL
    GROUP BY pubyear
    ORDER BY pubyear DESC
    LIMIT 15
""").df()
print(df)

Open Access#

List every stored is_oa value and its share of papers.

df = con.sql("""
    SELECT
        is_oa,
        COUNT(*) AS papers,
        ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS pct
    FROM papers
    GROUP BY is_oa
    ORDER BY papers DESC
""").df()
print(df)

Reprint Countries#

Count papers by reprint-author country.

df = con.sql("""
    SELECT
        reprint_country,
        COUNT(*) AS papers
    FROM papers
    WHERE reprint_country IS NOT NULL
    GROUP BY reprint_country
    ORDER BY papers DESC
    LIMIT 10
""").df()
print(df)

Subject Categories#

wos_subjects stores several categories in one string, separated by |. Split the field, drop blanks, and count.

df = con.sql("""
    SELECT
        subject,
        COUNT(*) AS papers
    FROM (
        SELECT TRIM(unnest(string_split(wos_subjects, '|'))) AS subject
        FROM papers
        WHERE wos_subjects IS NOT NULL
    )
    WHERE subject != ''
    GROUP BY subject
    ORDER BY papers DESC
    LIMIT 10
""").df()
print(df)

Recent Papers#

Return five recent papers that have an abstract. LEFT shortens the title and abstract in the result. has_abstract is Y or N.

df = con.sql("""
    SELECT
        uid,
        pubyear,
        first_author,
        LEFT(title, 80) AS title_snippet,
        LEFT(abstract, 120) AS abstract_snippet
    FROM papers
    WHERE has_abstract = 'Y'
    ORDER BY sortdate DESC
    LIMIT 5
""").df()
print(df)

Editions#

editions stores one or more edition codes in a single string, separated by |. Split the field the same way as Subject Categories.

df = con.sql("""
    SELECT
        edition,
        COUNT(*) AS papers
    FROM (
        SELECT TRIM(unnest(string_split(editions, '|'))) AS edition
        FROM papers
        WHERE editions IS NOT NULL
    )
    WHERE edition != ''
    GROUP BY edition
    ORDER BY papers DESC
""").df()
print(df)

Cited References#

Each row of paper_references is one bibliography entry. citing_uid is the citing paper. ref_uid values that start with WOS: match papers.uid. Replace WOS:001588455800012 with a uid from papers.

df = con.sql("""
    SELECT
        r.occurrence_order,
        r.ref_uid,
        r.cited_author,
        r.year,
        r.cited_work,
        LEFT(r.cited_title, 80) AS title_snippet,
        cited.uid IS NOT NULL AS matched_in_papers
    FROM paper_references AS r
    LEFT JOIN papers AS cited
      ON r.ref_uid = cited.uid
    WHERE r.citing_uid = 'WOS:001588455800012'
    ORDER BY TRY_CAST(r.occurrence_order AS INTEGER)
""").df()
print(df)

Authors#

authors_json is a JSON array of author objects. Unnest one paper at a time. addr_no matches addresses_json, and reprint is Y for the reprint author. ORCID is orcid_id. ResearcherID is r_id. Replace the uid below.

df = con.sql("""
    SELECT
        p.uid,
        author.seq_no,
        author.display_name,
        author.orcid_id,
        author.r_id,
        author.reprint,
        author.addr_no
    FROM (
        SELECT uid, authors_json
        FROM papers
        WHERE uid = 'WOS:001588455800012'
          AND authors_json IS NOT NULL
    ) AS p,
    UNNEST(from_json(
        p.authors_json,
        '[
            {"seq_no":"VARCHAR","display_name":"VARCHAR","full_name":"VARCHAR",
             "wos_standard":"VARCHAR","first_name":"VARCHAR","last_name":"VARCHAR",
             "r_id":"VARCHAR","orcid_id":"VARCHAR","reprint":"VARCHAR","addr_no":"VARCHAR"}
        ]'
    )) AS t(author)
    ORDER BY TRY_CAST(author.seq_no AS INTEGER)
""").df()
print(df)

Unnest addresses_json with the same from_json pattern. Field lists for both JSON columns are under Papers. organizations is semicolon-delimited.

Database Tables#

The 2025 extract is one DuckDB file at /kellogg/data/WOS/2025/db/wos2025.db. Open it read-only, as in Open a Connection.

Table

One Row Is

papers

One publication

paper_references

One cited reference. A paper with 40 references contributes 40 rows

paper_references.citing_uid is the citing paper. ref_uid values that start with WOS: match papers.uid. See Cited References.

These columns store several values in one string, separated by |: editions, doctypes, normalized_doctypes, keywords, keywords_plus, wos_headings, wos_subheadings, wos_subjects, fund_agencies, oa_types, and sdg_categories. Split them as in Subject Categories. authors_display and organizations inside addresses_json are semicolon-delimited. source_title is upper case.

Column types are string or int32. JSON columns are text. Open Authors and Affiliations for the author and affiliation fields. The reference-table fields are below.
